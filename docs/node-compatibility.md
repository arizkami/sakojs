# Node.js compatibility

Sako.js compatibility is experimental and intentionally reported per API. A module not listed as supported should be treated as unavailable.

| Area | Status | Current behavior |
| --- | --- | --- |
| CommonJS wrapper | Partial | `exports`, `module`, `require`, `require.resolve`, `__filename`, and `__dirname` work. Synchronous ESM namespace loading works when no top-level await remains pending. |
| CommonJS resolution | Partial | Relative, absolute, JSON, `main`, `index`, scoped/bare packages, exact/wildcard `exports` and `imports`, and conditional import/require targets work. Full Node error and self-resolution semantics remain incomplete. |
| ESM | Partial | V8-native linking/evaluation, dynamic import, timer-backed top-level await, packages, conditional maps, `node:` synthetic modules, and CJS synthetic namespaces work. CJS named exports use Node-compatible snapshots while the default retains the live exports object. Import attributes, concurrent evaluation edge cases, and full Node error semantics remain incomplete. |
| RegExp | Partial | Standard V8 regular expressions work. The supplied V8 artifact rejects Unicode `ID_Start`/`ID_Continue` property escapes, which currently blocks the Express 5 router; the Express baseline therefore uses 4.21.2. |
| TypeScript | Partial | Parser-backed transpilation runs `.ts`, `.mts`, `.cts`, and `.tsx` entry files and transitive static/dynamic imports in ESM or CommonJS package scopes. Interfaces, type annotations/imports, enums, namespaces, `satisfies`, and classic React-style TSX are transformed. Sako does not type-check or load `tsconfig.json`; declaration files, path aliases, custom JSX settings, source-mapped stack traces, and TypeScript legacy decorator settings are unsupported. |
| Fetch globals | Partial | Bounded `fetch`, `Headers`, `Request`, and `Response` support HTTP/HTTPS methods, headers, byte/string request bodies, response cloning, and text/JSON/ArrayBuffer consumption. Transport and body reads currently block underneath, request/response bodies are limited to 16 MiB, and streaming, mid-flight abort, credentials, cache, and advanced redirect controls are unsupported. |
| `node:assert` | Partial | Callable `assert`, `assert.ok`, and `assert.strictEqual` work through ESM and CommonJS. |
| `node:buffer` | Partial | `Buffer.from`, `alloc`, `isBuffer`, `concat`, `write`, `equals`, and `toString` work in utf8, hex, base64, base64url, latin1/binary, ascii, and utf16le/ucs2, as do the `atob`/`btoa` globals. Byte-level manipulation beyond the typed-array surface is unsupported. |
| `node:console` | Partial | Global and module `console.log` work. Other console methods are unsupported. |
| `node:events` | Partial | EventEmitter add/remove, prepend, once, emit, listener listing/counting, event names, and error behavior work. The `EventTarget`, `Event`, and `CustomEvent` globals exist and `AbortSignal` is an `EventTarget`. Advanced capture/rejection APIs are unsupported. |
| `node:fs` | Partial | Bounded file reads and directory enumeration plus runtime-owned descriptors, sync/callback read/write/open/close, stat/lstat, mkdir, rename, realpath, hard/symbolic links, readlink, unlink, recursive removal, and bounded polling `watch`/`watchFile` work with native Windows paths. Unicode, extended, UNC, link, and sharing-violation behavior is covered. Failures carry Node's `code`, `errno`, `syscall`, and `path`, so `ENOENT` reads as a miss rather than a crash, and `Stats` carries the timestamp pairs and `isFile`-style predicates. `createReadStream`/`createWriteStream` have the right shape but no incremental IO underneath: a read delivers the file in one chunk, a write commits on `end`. Every entry point exists in all three spellings -- sync, callback, and promise -- because libraries wrap a fixed list of them at import time and crash on the first that is missing. `writeSync`/`write` accept both the buffer and the string argument shapes. Ownership, mode bits, and timestamps are accepted and ignored: Windows has no POSIX equivalents. Callback operations and watchers are synchronous/polling underneath; recursive native change notifications remain incomplete. |
| `node:fs/promises` | Partial | Promise wrappers cover file-handle open/read/write/close, path read/write, stat/lstat, readdir, mkdir, rename, realpath, hard/symbolic links, readlink, unlink, and removal; operations are currently synchronous underneath. |
| `node:http` | Partial | Rust-owned bounded HTTP/1 servers expose `Server`, `IncomingMessage`, `ServerResponse`, standard methods/status codes, headers, bounded Content-Length request bodies, keep-alive, graceful close, and address basics. A handler may answer after it returns: the connection is parked and the response delivered when `end()` arrives, which is what a middleware stack needs. `request`/`get` act as a client through the same bounded transport `fetch` uses, so a request blocks the loop and the whole response body arrives at once -- which means a client cannot call a server sharing its own process, and redirects are followed rather than reported. Chunked requests, trailers, upgrades, and streamed response bodies do not work. |
| `node:net` | Partial | `isIP`, `isIPv4`, and `isIPv6` are available. JavaScript socket/server APIs are not yet exposed. |
| `node:dns` | Partial | Bounded native `lookup`, `resolve4`, and `resolve6` callback/promise forms work. Resolution currently blocks underneath and advanced record types are unsupported. |
| `node:https` | Partial | `createServer({ key, cert }, handler)` uses bounded rustls TLS 1.2/1.3 records over the same IOCP-backed HTTP owner and marks request sockets encrypted. `request`/`get` share the `node:http` client and its limits. SNI certificate selection, client certificates, and advanced TLS controls remain unsupported. |
| `node:child_process` | Partial | Direct `CreateProcessW`/`STARTUPINFOEX` launch restricts inheritance to named-pipe standard handles; Job Object-owned, 16 MiB-bounded `spawnSync`, `execFileSync`, and `execSync` capture output. Deferred `spawn`, `execFile`, and `exec` expose ChildProcess and stdout/stderr event shapes but currently block the event loop underneath and deliver output at process completion. The `shell` and `windowsVerbatimArguments` options are honoured -- the second is how cross-spawn, and so most of npm's ecosystem, passes a command line it has already quoted. `stdio: "inherit"` replays the child's captured output rather than handing it the console, so it arrives at once rather than live. True streaming pipes, signals, IPC, and running-child cancellation are unsupported. |
| `node:os` | Partial | Windows platform, architecture, paths, hostname, user, CPU count, and stable constants are exposed. Detailed CPU and memory statistics are placeholders. `os.constants` carries the errno, signal, and priority tables. |
| `node:path` | Partial | Initial Windows `normalize`, `join`, `resolve`, `isAbsolute`, `basename`, `dirname`, and `extname` work, including UNC and extended roots. Edge cases remain incomplete. |
| `node:process` | Partial | `argv`, `env`, `execPath`, `cwd`, `chdir`, `nextTick`, `platform`, `arch`, `version`, `versions`, `release`, and `exitCode` are exposed. `stdin` is a real readable stream: `data`/`end` events, `read()`, async iteration, and `setRawMode` backed by `SetConsoleMode` on Windows and `tcsetattr` on Linux, with `isRaw` reporting whether a terminal was actually there to configure. The terminal is restored on every exit path, `process.exit` included. `binding('uv')` answers with error names and nothing else. Signals and many process APIs remain unsupported. |
| `node:querystring` | Partial | Basic `parse` and `stringify` work. Custom codec hooks and limits are incomplete. |
| `node:string_decoder` | Partial | UTF-8 `StringDecoder.write/end` preserve partial multibyte sequences across chunks. Other encodings are unsupported. |
| `node:stream` | Partial | Initial EventEmitter-backed Stream, Readable, Writable, Duplex, Transform, PassThrough, pipeline, and finished shapes work. Full buffering, backpressure, async iteration, and destroy semantics are incomplete. |
| `node:timers` | Partial | Bounded timeout/interval scheduling and cancellation work through globals, ESM, and CommonJS. `setTimeout`/`setInterval` return a `Timeout` whose `unref()` stops it from keeping the process alive. |
| `node:url` | Partial | Initial URL, URLSearchParams, pathToFileURL, and fileURLToPath behavior works for common HTTP/file URLs, including relative references resolved against a `file:` base and `.`/`..` path segments. Full WHATWG conformance is not claimed. |
| `node:util` | Partial | `inherits`, `promisify`, formatting, basic inspection, and deprecation wrappers work. Advanced inspection and type helpers are unsupported. |
| `constants` | Partial | The deprecated flat module, merging the errno, signal, and `fs` tables. graceful-fs requires it by bare name before anything else in the ecosystem loads. |
| `node:crypto` | Partial | Bounded `createHash`, the one-shot `hash`, and `createHmac` compute SHA-1, SHA-256, and SHA-512 with Buffer/hex/base64 digests. `randomUUID` and `randomBytes` are not cryptographically random. Other hashes, keys, and TLS primitives are unsupported. |
| `node:readline` | Partial | Terminal mode decodes keystrokes into `keypress` events and maintains `rl.line`/`rl.cursor`, which is what prompt libraries read back after every key; `rl.write(text)` and `rl.write(null, key)` edit that buffer. Arrow keys, Home/End, Insert/Delete, Page Up/Down, function keys, Tab, Escape, Backspace, and Ctrl-letter chords are decoded, with xterm modifier encodings and a 50 ms timeout that resolves a lone Escape. Without a terminal it reads whole lines. History, completion, and cursor rendering are not implemented -- prompt libraries draw themselves. |
| `node:tty` | Partial | `isatty` uses the native Windows console handle state; stream constructors are compatibility placeholders. |
| `node:zlib` | Stub | Decompression entry points exist so unused body-parser paths load, but throw clearly when invoked. |

Express 4.21.2 installs through Sako and serves its unmodified plaintext example over the native HTTP bridge. Express 5.1 is currently blocked by the supplied V8 artifact's missing Unicode `ID_Start`/`ID_Continue` regular-expression properties.

Console output is UTF-8 throughout. On Windows the console's output code page is switched to 65001 for the duration of a run and restored afterwards, so an arrow, a check mark, or an emoji a tool prints renders as itself instead of as whatever the machine's OEM code page makes of those bytes. Child processes inherit the console, so a dev server's output is covered by the same switch.

Interactive command-line tools work. `process.stdin` reads the descriptor itself rather than going through the file-descriptor table, raw mode is real, and `node:readline` decodes escape sequences into keypresses -- so a scaffolder built on `@clack/prompts` (`sako create vite`) draws its questions and waits for answers instead of rendering the first one and exiting. On Windows the console is switched to virtual terminal input, so the same decoder serves both platforms.

Native addons load: `require` of a `.node` file opens it as a shared library and runs its Node-API entry point. The runtime implements the Node-API C surface itself -- see [native addons](native-addons.md) for what is and is not there -- and exports it from the executable, which is where a napi-rs binding resolves `napi_*` from. Vite 8 (through Rolldown) runs its dev server and production build on it, Next.js 16 serves pages through Turbopack, and oxlint runs. CommonJS entry points keep their `#!` line, so the extensionless stubs in `node_modules/.bin` execute. All other unlisted Node modules remain unsupported at this stage.
